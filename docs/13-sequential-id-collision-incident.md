## 2. 왜 지금까지 안 보였나

- producer가 폐기 건수를 `duplicates`라는 이름으로 집계했고, 1차 실행 때 "INSERT IGNORE 정상 동작(2.3%)"으로 기록했다(오판 1). 조용히 버리는 쓰기에 지표·알림이 없었다.
- 5코인 시절 일 단위·거래량 기준 대조가 99% 이상이었다. 그러나 건수 기준으로 재확인하니 09-03~09-09 5코인 구간 손실이 **6.38%**였다. 거래량 가중 대조는 소액 체결 손실을 숨긴다.
- `sequential_id` 전역 유일은 문서로 확인된 적 없는 가정이었다.

## 6. 교훈 (기록용, "왜 그렇게 했나"의 답)

1. 외부 ID의 유일성 범위는 프로파일링으로 검증한 뒤 키에 넣는다. 여기선 `(market, sequential_id)`.
2. 조용히 버리는 쓰기(`INSERT IGNORE`)에는 버린 행 수 지표와 알림을 붙이거나, 격리 테이블로 보낸다. "duplicates"라는 이름이 유실을 정상으로 위장시켰다.
3. 정합성 불일치는 소스 탓으로 결론내기 전에 **독립 수신기로 소스를 재현**한다. 오늘 이 절차 하나가 결론을 뒤집었다.
4. 대조는 거래량이 아니라 **건수·ID 단위**로, 소스 원장 기준으로, 원장 보존 창(7일) 안에 매일 자동으로 돈다. → 관찰 뒤 1순위: `reconcile_trades` DAG(자동 대조·백필) + dbt `unique_combination_of_columns(market, sequential_id)`·커버리지 테스트.
5. 원장 REST를 쓰는 작업은 직렬화·중앙 페이싱(오늘 동시 실행으로 429).
